Una ayuda · el contrato de datos

Para que Don Chente edite sin tocar código

El menú vive en un archivo aparte. Él cambia precios ahí; la página se arma sola.

menu.json — un ejemplo del que pueden partir
// cada plato es un objeto. Don Chente solo edita este archivo. [ { "nombre": "Desayuno chapín", "categoria": "desayunos", "precio": 30, "descripcion": "Huevos, frijoles, plátano y tortillas", "foto": "img/desayuno-chapin.jpg", "alt": "Plato con huevos, frijoles volteados y plátano frito" } ]

Su componente hace fetch del archivo, guarda los platos en useState y pinta una tarjeta por cada uno. El alt ya viene en el dato: accesibilidad desde el origen.

DATOS · el contrato · úsenlo o mejórenloseparar datos de presentación
Esta slide da un empujón sin resolverles el parcial: les muestro la FORMA de los datos (el contrato), no el componente. Es la respuesta a la queja 3 ("cambiar el menú yo solo") — separar datos de presentación es una idea grande y vale la pena regalarles el patrón. Notá que el alt del plato viene dentro del JSON: así la accesibilidad no es un parche al final, es parte del dato. Pueden usar este esquema tal cual o mejorarlo (agregar id, disponible: true/false, etc.). Aclarales que fetch de un archivo local puede pedir servir la página (Vite ya lo hace), por si les tira error de CORS al abrir con doble clic.
